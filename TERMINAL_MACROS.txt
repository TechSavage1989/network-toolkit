NETWORK TOOLKIT 1.17.35 - TERMINAL MACROS AND MULTI-TERMINAL INPUT

Workspace layout

Use the sidebar's Saved, Recent and Macros vertical tabs. Macros contains
Library and Runs views; its contents scroll independently of the console.
Use Hide sidebar to leave a slim tab rail, and Show sidebar or a tab to reopen
it. Drag the divider to resize; double-click it or press Enter/Space to hide
or restore it. Arrow keys resize; Home resets the width. The expanded width
is remembered. There are no duplicate Sidebar or Macros toolbar toggles.

Recording and active runs have a compact activity control in the terminal
bar. Use it to return to recording or run controls from any sidebar tab.

Choose where input goes

Use the compact Send to row above the terminal:
  Current terminal - the active connected session.
  Selected terminals - open recipient details to choose connected sessions.
  All connected terminals - every available connection in this app workspace.

The main window can target sessions in its linked detached windows. A detached
window targets only sessions assigned to that window. Separate application
processes have separate connections; All does not reach those processes.
Use recipient details to check the destination names before sending. A macro's
destinations are fixed when you run it; changing panes or the selector cannot
redirect it.

Use Command bar in the terminal toolbar to hide or restore the Send to row.
Expand it for multiline editing; recipient details open as a floating panel.
Composer visibility and the selected sidebar tab are remembered.

Insert only and Run command

Insert only types one line into the selected terminals without pressing Enter. Use
it to prepare input for review. It rejects embedded line breaks.

Run command executes the entered command or command list. Ctrl+Enter does the
same from the command box. Each nonempty line becomes a command in a temporary
run: the runner waits for a prompt before sending the next command, advances
common pagers, and collects output separately for each destination. Open the
Macros tab and choose Runs to see its progress and Output. For a different
prompt or timeout, save a macro and configure its timing instead.

Create and organize macros

Open the Macros sidebar tab, choose Library, then New. Give the macro a name
and enter one command per line. Save macro, then click its name or play button.
The default confirmation shows the destinations and expanded commands before
Run. Each destination progresses at its own pace, so a slow terminal does not
hold up the others.

Other convenient starting points:
  Record captures commands from the current terminal. Pause recording when
  needed, then Stop and review. Replace sensitive literals with secret variables
  before saving; a recording is a draft to review.
  Save last command and Save last paste create editable macros from input
  captured in the current terminal.
  Pin in Macros adds a quick-access favorite in the library. A shortcut such as
  Ctrl+Alt+1 uses your chosen run-confirmation setting.

Search matches names, descriptions, folders, tags and command text. Use folders
and comma-separated tags to group tasks. Right-click a macro, or use its ...
button, to preview, edit, duplicate, pin/unpin, export or delete it. Deletion
uses the session deletion-confirmation preference.

The Library More button opens Import macros and Export library. Last command
and Last paste are separate shortcuts directly below New and Record.

Export saves macro JSON. Import adds copies while keeping existing macros;
imported copies receive new IDs and cleared shortcuts. Review their commands,
then assign shortcuts and startup bindings as needed.

Run confirmation

At the top of Macros, in either Library or Runs, choose Confirm runs:
  On shows the destination and command preview before running.
  Multiple terminals only confirms runs with more than one destination.
  Off starts the selected macro directly using available defaults.

The run dialog also has Show this confirmation before running. Uncheck it
and run successfully to turn future prompts off. Canceling, missing required
values or a failed submission does not save a changed checkbox preference.

Missing required values, including secrets, still open the parameter dialog.
Right-click a macro and choose Preview and run to inspect any run regardless
of the default confirmation setting. Destinations remain fixed per run.

Advanced steps and variables

Advanced steps supports reordering, disabling and deleting individual steps:
  Command + Enter - send a command and press Enter.
  Insert text - send text, including line breaks, without adding a final Enter.
  Key - Enter, Tab, Escape, Ctrl+C/Z/D, arrows or Backspace.
  Wait for text / pattern - wait for matching output using an RE2 expression.
  Delay - wait for a specified number of milliseconds.
  Pause for review - wait until you choose Resume or Step.

Write {{variable}} in a step, then use Detect variables to configure its label,
default and whether it is required or secret. Built-in {{host}}, {{username}}
and {{session}} resolve separately for each destination. Custom values are
single-line text; substitutions are literal and do not evaluate local scripts.
Secret defaults are never stored. Enter secrets at run time; previews mask
them, and the runner redacts supplied secret values from its output export.

Timing and terminal behavior

Wait for the prompt after commands is on by default, with a 30-second timeout
per step and 100-millisecond pacing. The default recognizes common short shell
and network-device prompt lines ending in #, >, $, or %. Set a device-specific
Prompt pattern when necessary; prompt and wait patterns use Go's RE2 syntax,
which supports inline flags but not lookaround or backreferences. Escape
punctuation when you need a literal match. Wait steps can override the timeout.

Each destination respects its current Auto scroll setting when a run starts.
On follows the bottom, including before a delayed first command; Off keeps
the visible position. Manual wheel or scrollbar use pauses following through
later macro steps and paging. Scroll to bottom or manual Ctrl+C/Ctrl+Z resumes
following. Resizing retains the top visible line when paused.

Automatically continue at --More-- prompts is visible beside the macro
commands. Enable it to advance supported device paging prompts during the
run. The preview offers the same choice for one run without changing the
saved macro. It does not change the console Auto scroll setting.

Auto scroll moves the console view as output arrives. It does not send page
continuation keys to the device. A macro's own automatic paging setting
controls continuation while that macro owns the terminal.
If prompt waiting is off, final capture normally ends after one second without
new output, bounded by the configured timeout; very short timeouts shorten the
idle period. Use prompt waiting or an explicit wait for slow or delayed output.

Control a run and retrieve output

Pause holds execution; Resume continues; Step advances one step then pauses.
Stop stops the macro and keeps its terminals connected. Interrupt also sends
Ctrl+C. Typing manually in a destination cancels automation for that terminal
before your input is sent. Other destinations can continue independently.
Disconnecting or reconnecting stops the old connection's run; it cannot resume
on the replacement connection. Start a new run when ready.

Each run's Output button offers All run terminals or one terminal, plus Select
all, Copy and Export output. This capture is independent of the visible console
buffer, so long output remains available even after its lines leave scrollback.
Output is retained in memory without a fixed byte cap; available memory is the
practical limit. The app retains the last 20 finished runs plus active runs.
Use Clear on a finished run or Clear all above Runs to remove retained history
and its captured output. Active and paused runs stay until stopped. Clearing
applies across linked windows, within the requesting window's session scope.
Cleared runs cannot be reopened; export output you want to keep first.
Closing the app also clears run history and captures; export anything you need to
keep. Saved macros remain in the shared library.

Run automatically for saved sessions

In the editor, expand Run automatically for a saved session and select On
connect and/or On reconnect for each desired saved session. One macro can have
several bindings, and a profile can have several startup macros. Startup uses
saved defaults and cannot prompt for required values: provide a default for
every required variable; required secrets must be run manually. A macro with
missing required values is skipped with a message. Startup macros for the same
profile run sequentially; if a run fails or stops, remaining bindings are
skipped. Review and test a macro manually before binding it to connections.

Practical starters

For an SSH Linux shell, choose New, name it Linux quick check, and enter:
  hostname
  uptime
  ip -brief address
  ip route
These are read-only diagnostics; ip requires the iproute2 tools on that host.

For an interface-specific Linux check, use this command and Detect variables:
  ip address show dev {{interface}}
Mark interface required, then supply the actual name, such as ens192, in the
run preview. Choose Selected terminals when the command fits only some hosts.

On network devices that support them, a read-only starter might be:
  show version
  show interfaces
Command syntax varies by vendor and operating system. Adjust the commands and
prompt pattern for the actual devices before sending to multiple terminals.

Limits: 500 saved macros, 1,024 steps per macro, 64 KiB text per step, a 4 MiB
library file, and 1,000 startup bindings. Output capture has no fixed byte cap.
