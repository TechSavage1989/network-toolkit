Network Toolkit native WebView2 runtime bootstrap

This application's runtime-discovery and environment-creation code adapts the
Go-native loader from wailsapp/go-webview2, itself a Go port of John Chadwick's
OpenWebView2Loader. The implementation is compiled into the application.

Scope of the adaptation:
- Uses Go's standard library and the existing native COM callback support.
- Searches only the installed Evergreen WebView2 Runtime registration, with
  machine registration before user registration in the 32-bit registry view.
- Does not fall back to Edge Beta, Dev, Canary, or the regular Edge browser.
- Reads a bounded literal local installation path and validates its version,
  file type, PE format, and x64 architecture before normal Windows DLL loading.
- Uses LoadLibraryExW with LOAD_LIBRARY_SEARCH_DLL_LOAD_DIR and
  LOAD_LIBRARY_SEARCH_SYSTEM32; no PATH or current-directory DLL search.
- Calls the same CreateWebViewEnvironmentWithOptionsInternal runtime entry
  point as the pinned Go-native loader and adapts the completion interface.
- Retains the installed runtime module until process exit after invocation.
- Preserves the application's private profile and existing WebView restrictions.

No upstream native_module implementation, embedded DLL bytes, runtime DLL
extraction, manual PE mapping, runtime installation, or external Go dependency
is included in this adaptation. The optional upstream native_webview2loader
build-tag path is not used.

This is the community Go-native bootstrap approach, not Microsoft's separately
distributed WebView2Loader.dll or WebView2LoaderStatic.lib. The installed
Microsoft Edge WebView2 Runtime remains a requirement. Its internal bootstrap
entry point is a compatibility boundary that can require a future app update.
