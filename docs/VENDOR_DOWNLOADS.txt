NETWORK TOOLKIT 1.17.35 - IEEE VENDOR DOWNLOADS

Downloads retain the previous database until all four official IEEE registries
have downloaded and passed the normal CSV/count validation. Imports and bundled
database use remain available when the current network cannot reach IEEE.

DOWNLOAD PATH

1. Go HTTPS, TLS 1.2 minimum, with standard environment-proxy routing.
2. For TLS protocol/record/handshake failures only, one Go TLS 1.2/HTTP1.1 retry.
3. On Windows, if that retry also has a TLS protocol failure, one OS-native
   WinHTTP attempt. This uses Windows TLS and system/per-user proxy discovery
   when HTTPS_PROXY is unset. A supported explicit HTTP proxy is retained;
   a matching NO_PROXY remains direct. Unsupported encrypted/authenticated
   environment-proxy settings are reported without changing their route.
4. A native error positively identified by Windows as a channel-only TLS
   failure gets one fresh native TLS 1.2 session. The same context/deadline and
   proxy route apply. A certificate, mixed, unknown or missing failure flag
   never triggers this retry.

Certificate errors and actual HTTP refusals do not trigger an alternate client.
Every request uses HTTPS on standards-oui.ieee.org, with no custom port/userinfo.
WinHTTP automatic redirects are off. At most two manually validated redirects
can remain on that same official HTTPS destination. Certificates are checked by
the selected stack; no ignore-certificate flags or plaintext downgrade exist.
Windows TLS accepts 1.2/1.3, or only 1.2 when its OS does not support the 1.3 flag.
The native request does not accept cookies or automatic HTTP authentication.

Error 12175 includes Windows secure-failure callback flags and descriptions:
unknown certificate authority, invalid certificate, incorrect hostname,
invalid date, revocation status, revoked certificate or TLS channel failure.
All reported reasons and the complete hexadecimal mask are retained. A missing
callback reason is reported explicitly instead of guessed to be a trust error.
Callbacks copy only a DWORD into atomic per-request state behind a unique
integer token. Native context stores no Go pointer; request close removes the
token, so late callbacks cannot be confused with a reused native handle.

All attempts share one caller deadline of 20 seconds per registry. Native
synchronous requests are owned by a worker with finite phase timeouts and
context checks. Cancelling returns immediately; the worker closes its handles
after its outstanding native call finishes. An active synchronous handle is
never closed from a separate cancellation thread, and a late result cannot
change the database. Reads retain the existing 16 MiB limit per CSV.

No external downloader or PowerShell process is launched. Windows loads its
own WinHTTP DLL by an absolute path obtained from GetSystemDirectoryW. The
portable package has no companion downloader DLL or new Go module dependency.

VERIFICATION

Portable fixtures check order, shared deadlines, TLS/redirect/cookie/auth
options, proxy routing, size limits, cancellation/handle lifetime and unchanged
database state after failure. The Windows binding and test binary compile for
Windows x64. Native Windows execution and the user's proxy/network path are
unavailable in the build environment. The earlier successful Linux IEEE check
does not validate this Windows path. A service refusal, TLS inspection policy
or broken proxy can still prevent all clients from downloading successfully.
