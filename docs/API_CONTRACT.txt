NETWORK TOOLKIT 1.17.41 - INTERNAL CONTRACT

TRANSFER SERVER AND FILE MANAGER API (1.17.38)

All routes use the app's existing X-Session-Token, Host, Origin and local-session
authorization policy. None is available to unauthenticated network clients.

GET /api/transfer/server?protocol=sftp|tftp returns server status:
  {running,protocol,root,address?,bind,port,access,overwrite,started?,
   active,bytes,transfers:[{time,peer,operation,file,bytes,status,detail?}],
   fingerprint?}
POST /api/transfer/server (JSON):
  {action:"start", protocol:"sftp"|"tftp", root:"<absolute folder>",
   bind:"<local IP>",port:1..65535,access:"read"|"write"|"readwrite",
   overwrite:false,username?:"...",password?:"<transient secret>",
   authorizedKeys?:"<absolute public-key file>"}
  {action:"stop",protocol:"sftp"|"tftp"}
  {action:"setroot",protocol:"sftp"|"tftp",root:"<absolute folder>"}
The setroot action only changes the local file manager's root while stopped;
it never starts a listener. A running server's root cannot be changed.
No server starts on app startup; running listeners close on application exit.

GET /api/transfer/files?protocol=sftp|tftp&path=<root-relative path>
GET /api/transfer/files?protocol=sftp|tftp&preview=<root-relative file>
  Browser response includes root, path, parent, and sorted entries with name,
  path, directory, size and modified. Text previews limited to 128 KiB.
POST /api/transfer/files (JSON):
  {protocol,action:"mkdir"|"rename"|"move"|"copy"|"delete"|"upload"|"download",
   path:"<root-relative file/folder>", newPath?,localPath?,
   overwrite?:false,confirm?:false}
  Deletes require confirm=true and directory deletes require empty folders.
  Absolute paths, parent traversal, reparse link escapes and symbolic links
  within the root are rejected. Local file manager actions are independent
  of remote network permissions.

GET /api/transfer/local?path=<absolute local directory>
GET /api/transfer/local?preview=<absolute local file>
  Authenticated local filesystem browser and a read-only 128 KiB text preview.
POST /api/transfer/local-files (JSON):
  {action:"mkdir"|"rename"|"copy"|"delete", path:"<absolute path>",
   newPath?:"<absolute path>",overwrite?:false,confirm?:false}
  Local deleting requires confirm=true. Removing a drive/filesystem root is
  rejected. Deleting directories is nonrecursive (only empty directories).
  Symlinks and special files are rejected for mutation.

Explorer file-copy actions support directories recursively with a maximum
10,000 entries and 64 levels. Per-file copied data is capped at 4 GiB.
Copy does not delete any destination content, and symlinks are not followed.
Items are processed sequentially with an optional stop-after-current request.
There is no wire-level TFTP remote folder listing or resumable upload.

SFTP server: SSH password and/or authorized public keys, Ed25519 host key,
SFTP version 3 file operations only (no shell/exec/PTY), user-chosen root,
read/write permissions, overwrite protection and server transfer logs.
TFTP server: RFC1350 and RFC2347/2348/2349, binary octet mode only,
per-transfer UDP sockets, upload/download, retries, overwrite control and
transfer logs. Access is anonymous; use only on trusted networks.

FILE TRANSFER DIAGNOSTICS (1.17.36)

POST /api/jobs supports tool: sftp and tool: tftp. Both run through the
standard event/job/cancellation system. Results contain operation metadata
and events may include transfer-progress {bytes,totalBytes,percent?}.

SFTP options:
  operation: fingerprint|list|stat|download|upload|mkdir|rename|remove|rmdir
  port: 22 by default
  username, authMode: password|key
  password (transient), keyPath, passphrase (transient)
  fingerprint: trusted SHA256 host-key fingerprint required except when
    operation=fingerprint, which inspects the presented key without signing in
  remotePath, localPath, newPath
  timeoutMs: 10000 default
  overwrite: false default, confirmDelete: false default

The SFTP implementation uses SSH plus the version 3 SFTP subsystem. An
unverified SSH host key prevents authentication and file operations. File
operations are per job, not a reusable SSH session. Uploaded passwords and
passphrases are excluded from returned and stored jobs. Remote delete requires
confirmDelete=true. Overwriting files requires overwrite=true.

TFTP options:
  operation: download|upload
  remotePath, localPath, port: 69 default
  blockSize: 1428 default (RFC 2348)
  timeoutSec: 3 default (RFC 2349), retries: 5 default
  overwrite: false default

TFTP is binary octet mode with optional blksize/timeout/tsize negotiation,
and retransmissions. No username, password or encrypted session exists.

GET /api/transfer/local?path=<absolute-or-relative-local-path> returns:
  {path,parent,separator,roots:[...],entries:[{
     name,path,directory,size?,modified?
  }]}

This endpoint is GET-only, authenticated as a local application API, and
returns metadata for at most 2,500 entries. Selection alone never reads file
contents. Actual file operations require the user's explicit start action.

MACRO RUN HISTORY (1.17.30)

DELETE /api/terminal-automation/runs/{id} removes one finished run and its
retained output. Active or paused runs return 409; missing runs return 404.
DELETE /api/terminal-automation/runs clears finished runs available to the
requesting window. Both return {cleared:[runIds]}; an empty result is [].
Authentication and detached-session capability checks apply to both routes.
A linked window cannot clear a mixed run that includes outside sessions.
Clearing never closes terminals or edits saved macro definitions.

The client discards older in-flight run snapshots after a successful clear.
Polling removes stale output previews and composer output links when another
window clears history. The full retained run list is accessible.

The Library More button uses the body-level floating menu with keyboard
navigation, Escape, outside-click dismissal and visible import/export actions.

ENTRY DETAILS PRESENTATION AND RESPONSIVE CONTROLS (1.17.20)

entryDetails is a presentation preference object, separate from tool inputs.
It stores width, height, hidden and dock. Width accepts integers 260..700,
height 80..650, hidden requires true, and dock accepts auto/right/bottom.
Defaults are 350, 260, false and auto. Effective sizes clamp to the available
workspace without overwriting remembered expanded dimensions. These settings
apply to the standard selected-entry pane used by diagnostic result lists.
Discovery and packet inspector preferences retain their separate scopes.

The entry divider supports pointer resize, keyboard arrows (10px or 30px
with Shift), Home, double-click, Enter and Space. Visibility preserves the
selected record and mounted reader. Full collapsed rails reopen their panel.
Responsive text controls preserve icon-only controls and terminal interaction.

Packet DHCP focus combines decoded DHCPv4 with UDP ports 67/68 and 546/547.
DHCPv6 remains a UDP inspection path; no DHCPv6 field decoder is claimed.
Named task and quick-filter focus replace unrelated packet search/protocol
constraints. Explicit Search and Display filter controls still combine.
No new traffic is generated and the retained recording is not modified.

prepare(next) enhances detached result templates before live reconciliation,

Collapsed panel rails reveal the existing panel through its normal visibility

PACKET INSPECTOR PRESENTATION (1.17.18)

remain valid and inspectable. The packet detail endpoint is unchanged.

Quick guide disclosure state survives refreshes. Packet details presentation

GUIDED PACKET TROUBLESHOOTING (1.17.17)

GET /api/packet-captures/{id}/troubleshoot reviews the entire immutable retained
packet snapshot. Display filter, search, protocol and pagination parameters do
not narrow it. Existing authentication and terminal-window restrictions apply.
The report returns packetCount, duration, summary, scope, limitations, metrics
and findings. Findings contain id, severity, title, observation, meaning,
nextSteps, count, packetNumbers and filter. At most ten example packet numbers
are retained per finding; filters use the existing frame.number grammar.

The analyzer never sends traffic or modifies packet records. It correlates
visible requests/replies, reports supported observations and exposes capture
visibility limits. Capture-event loss and overwritten retention are distinct
from network loss. Encrypted content is not decrypted. No supported finding
does not establish network health. See PACKET_TROUBLESHOOTING.txt for scope.

Guided tasks affect display views only. Recording keep filters remain explicit
advanced controls. The troubleshooting report covers all retained traffic,
and its copy/save output preserves scope, findings and suggested next checks.

Shared sidebar controls render only chevron SVGs. Descriptive action/panel
captions remain in title and ARIA attributes, not visible button text.

MACRO SCROLL AND CONFIRMATION (1.17.15)

Manual macro runs, executed composer sends and startup bindings call the
current-scroll helper once for each fixed destination, after required-value
validation and before submission. It never changes Auto scroll or its epoch.
Polling and later steps never reapply the start behavior. Existing shared
output hooks follow only while the current per-session preference is true.

Before an actual terminal fit, paused normal-buffer sessions mark their top
visible line. After resizing they restore that marker; following sessions
scroll to the bottom. A newer scroll epoch prevents stale restoration. The
temporary marker is always disposed, including failed resize operations.

The Confirm runs header maps On/Multiple terminals only/Off onto the existing
always/multiple/never preference. The run preview checkbox commits only after
a successful run submission. Required runtime values always remain enforced.
The heading control collapses the sidebar and its vertical rail reopens it;
there are no duplicate Sidebar or Macros toolbar toggle buttons.

terminalSidebarTab is saved/recent/macros and defaults to saved. A restricted

terminalComposerCollapsed is boolean, default false. terminalMacroConfirmation

TERMINAL AUTOMATION (1.17.12)

Serial /api/terminals/{id}/line-ending updates the saved in-memory reconnect
request and metadata through the same ownership check as other controls.
New macro runs use the current serial Enter setting; active runs keep their
original destination settings.

Authenticated /api/terminal-automation routes expose targets, library, runs,
send, run control and run output. Targets contain id plus transport generation.
Every write verifies both. Reconnect retains the tab ID but replaces its
transport generation and ends old output subscriptions. Macro run targets
cannot be changed after Start. Main-window automation can address linked
sessions; detached tokens remain restricted to assigned session IDs. Mixed
runs cannot be enumerated, controlled or exported by a narrower capability.

The separate Network_Toolkit.macros.json library uses validated typed schemas,
a 4 MiB limit, anchored regular-file reads and atomic writes. PUT must include
the SHA-256 revision from GET; conflicting windows receive 409. Secret parameter
defaults are removed. Runtime values are never added to persistent settings.
Storage relocation includes this library; an independent terminal workspace
receives one initial copy and is not overwritten on subsequent launches.

Execution subscribes to output independently of the bounded display event
ring. Pause/step gates include automatic pager writes. Manual user input
cancels that destination's queued macro steps; terminal protocol replies do
not. Stop keeps the connection alive, and Interrupt also queues Ctrl+C.
Output remains in memory for at most 20 retained runs until process exit.

DECORATION INDEX LIFETIME (1.17.11)

The bundled xterm SortedList stores decorations keyed by marker.line. A marker
sets that key to -1 during disposal. With deferred removals and overlapping
viewport retention, binary search by the mutable key could miss exact entries
and leave the index unsorted, hiding valid colors indefinitely after scrolling.
delete now locates the stored object by identity, guards an already-queued
index and retains batched physical cleanup. Insert flushes pending deletions
before indices can move; delete retains the existing insertion flush.

The patch is isolated to that method and can be reproduced or verified with
scripts/patch_xterm_decoration_index.py. SOURCE.json keeps both upstream and
patched hashes. Normal source builds use the included asset and need Go only.
Regression coverage uses the real decoration service, row factory, render
service and RAF debouncer, plus actual-browser computed colors. The highlighter
recognizer, palette, ANSI policy, terminal stream and copied text are unchanged.

NEUTRAL FOREGROUNDS, SEARCH CLEAR AND TLS REASONS (1.17.10)

Semantic display colors apply to default and neutral foreground text when its
background matches the console and it is neither inverse nor invisible. Neutral ANSI
text roles honor a custom chromatic slot; RGB colors are eligible when equal
to the current normal foreground or within 32 channel values of gray. This
policy is evaluated against the current palette without changing buffer cells.
Explicit background colors qualify only within 32 RGB values of the console.
It removes the plain/colored boundary caused by explicit white before SGR0.

Clear search empties the shared query/result and clears decorations/selections
in existing terminal sessions, retaining case/visibility and search focus.

WinHTTP secure-failure callbacks copy their DWORD into an atomic field keyed
by a unique opaque request token. No Go pointer is stored in native context.
Request close removes the token; late callbacks cannot target a reused handle.
The callback is threadsafe and does no I/O. Error 12175 reports every known
flag plus the complete mask. Only an exact channel-only failure gets one new
native session with TLS1.2. Missing, mixed, certificate and unknown flags stop
without this retry. The same context, route, redirects and validation apply.

SCROLLBACK FIRST REPAINT AND WINDOWS HTTPS (1.17.9)

A viewport move with unchanged buffer base and stable existing markers finishes
the supported visible highlight queue synchronously in onScroll. This runs
before the renderer paints newly exposed rows. Buffer growth and marker shifts
from scrollback trimming use the parsed-write batch path, avoiding a full scan
per output newline. Existing semantic records remain keyed to their markers,
with unchanged decorations retained. The real bundled DOM row factory and
decoration index are exercised in Node fixtures; renderer code is unchanged.

Only after both Go attempts fail with a retryable TLS protocol error does
Windows invoke WinHTTP. The caller shares the original per-file 20-second
deadline. No explicit HTTPS_PROXY selects automatic system/per-user proxy
settings; a supported explicit HTTP proxy remains named, and a matching
NO_PROXY remains direct. Unsupported encrypted/authenticated proxy settings
are reported instead of silently changing route or exposing credentials.

WinHTTP is loaded from the OS system directory only. Requests use secure
port443, TLS1.2/1.3 (TLS1.2 alone if the OS rejects the newer flag), normal
certificate checks, disabled cookies/automatic authentication and disabled
automatic redirects. Manual redirects allow at most two hops to the same
official HTTPS host. Native reads retain the 16MiB guard and normal CSV/store
validation. No process, script, companion DLL or new Go dependency is added.

A worker owns synchronous native calls, handles and buffers. Cancellation
returns immediately to the caller, which cannot publish a late result. The
worker checks context between calls, supplies finite remaining phase timeouts
and releases its handles on return. It never closes an active synchronous
request from the cancelling thread. Native execution is not available here;
the driver is fixture-tested and its bindings/test binary cross-compiled.

TERMINAL REPAINT AND OUTPUT DESTINATIONS (1.17.8)

onWriteParsed enqueues the visible normal-buffer rows and starts one bounded
scan immediately. Remaining work stays queued; a batch always processes at
least one logical line even when the elapsed-time budget is already exhausted.
Existing marks retain immediate parsed-write reconciliation for ANSI/hidden
rewrites, including marked rows beyond the new-row batch budget.
Decoration insertion/removal records absolute dirty paint rows. After each
batch the public Terminal.refresh API receives one clipped viewport-row range.
Disabling/disposal also repaints removed marks. An unchanged scan creates no
paint request, so the onRender verification pass terminates naturally. No
terminal stream, ANSI cell attributes or scroll/input state is rewritten.

Output jumps capture their chosen block before waiting for archive parsing.
In retained console rows, screenOutput supplies the first/last logical line
with the same echo exclusion and idle-prompt removal used by Select/Copy.
selectLines covers every wrapped physical row, followed by scroll/focus under
input suppression. When the block start has left scrollback, the preview
selects the first/last text line and scrolls there. Copy output still copies
the complete captured block. Jumps pause follow for the target session only.

VENDOR HTTPS COMPATIBILITY AND TERMINAL CONTROLS (1.17.7)

Each IEEE download owns an isolated HTTP transport and one20-second context.
TLS protocol/record/handshake errors may trigger one TLS1.2+HTTP/1.1 retry using
the same official HTTPS destination, proxy configuration and deadline. Neither
profile disables certificate verification. HTTP errors, certificate failures,
unsafe redirects and cancellations are not compatibility retries. Source URLs
and every redirect must retain https://standards-oui.ieee.org without userinfo
or an alternate port. CSV size/validation and atomic database publication are
unchanged. User-Agent tracks the app version. HTTP403/418/429 and final TLS
failures include browser-download/CSV-import guidance. The UI appends a previous
database notice only when the server has not already supplied one.

Display is inserted directly before terminalToolsToggle. terminalSearch starts
without the hidden class; initial rendering does not call focus on its input.
Closing/reopening search and the existing key shortcuts remain available.

Terminal highlight kinds add command, field, protocol, value, number and comment
to the six existing roles. These keys are allowlisted in frontend/backend
appearance normalization and follow normal settings/view/workspace transfers.
Syntax roles use command position and common vendor grammar, not a device-health
inference. Quoted comments/objects and zero-count/negated errors are protected.
Interface tables accept tight spacing and compact address/up-down boundaries;
zero octets are not treated as standalone zero counters. Up to8192 visible
decorations and256 matches/logical line are allowed with the same time/row
budgets. ANSI/hidden/inverse/background protections and decoration reconciliation
remain intact. Copy-on-click keeps its earlier token categories so added syntax
coloring does not turn all command input into copying controls. Research scope
and primary vendor references are recorded in TERMINAL_HIGHLIGHTING.txt.

COMPLETE LIVE COMMAND OUTPUT (1.17.6)

The command archive seals parsed physical rows before they leave the shadow
terminal, joining wrapped text without wide-character padding. Immutable text
chunks retain the complete prefix; only the editable tail uses terminal cells.
Writes are split to4096 bytes/UTF-16 units. Live capture has no per-command byte
or row cutoff and no completed-text byte eviction, within the existing50-block
history. Memory grows with captured output; clear/dispose releases the chunks.

Select/copy/jump capture the chosen block, wait for its queued parser work and
then read its complete output. Availability checks inspect small archive state
instead of concatenating the full output on each render. Parser failures reject
the action. A new output-source choice does not retarget an operation in flight.

The existing4MiB/session transfer budget is separate. A shortened snapshot keeps
the final suffix on UTF-8/line boundaries and marks truncated=true, without
mutating live chunks. Background checkpoints assemble only the bounded suffix.

SESSION LIBRARY (1.17.2)

terminalRecent is an ordered list capped at 50 safe connection configurations
with id, name and lastUsed (nonnegative integral epoch milliseconds). It never
persists transport requests, secrets, session identifiers or transcripts.
Protected credential references use the same nonsecret profile schema.
terminalSidebarCollapsed, terminalRecentCollapsed, terminalSavedCollapsed and
terminalSessionConfirmDelete are booleans. Missing/invalid confirmation values
use the enabled default. Existing terminalProfiles supply Saved entries.
These fields are allowed in workspace display/checkpoints and independent
workspace seeding. Single-session detached views keep their narrow scope.

Direct opening follows normal credential resolution, validation, ownership,
view-state handling and captured pane placement. A retained recent tab is
selected while live and explicitly reconnected only while closed/error. Saved
entries also reuse matching retained tabs unless Open in new tab is chosen. After
its removal or an app restart, its safe settings create a new connection.
Unlinked SSH secrets are requested in a sign-in form and never saved by it.
Creating a new saved entry at the 100-entry UI limit does not evict another.

Context targets carry their list kind, id and content signature. Changed or
removed targets cannot be acted on through a stale menu or confirmation.
Clear Recent confirms the captured entries, preserving additions or updates
that occur while its modal is open. List removal never deletes live tabs or
saved vault credentials. All profile-removal UI paths use the same configurable
confirmation. List sections scroll separately from the existing console, which
is moved into the sidebar layout without replacing terminal DOM or buffers.

Executable hosts embedded HTML, JavaScript and CSS on 127.0.0.1 with random free port.

LOCAL NETWORK SCOPE

ping / tcp accept options.scope="subnet". Discovery always uses the subnet
engine, including for one IPv4 address. Device check rejects subnet scope.
Other single-target options retain their behavior. The network target is a
string containing one or more literal IPv4 scopes separated by commas,
semicolons or ASCII whitespace. Accepted entries are individual IPv4 hosts,
CIDRs, address/dotted-mask, inclusive full-address ranges, last-octet ranges
such as 192.168.1.1-254, and final-octet wildcards such as 192.168.1.*.
Spaces/tabs around slash and hyphen operators are allowed. IPv6 and hostnames
are rejected before any probe, without resolution. Repeated scope separators
are ignored. Empty lists and invalid/reversed ranges are errors.

CIDR/mask host bits are masked. CIDR and wildcard scopes omit their network
and broadcast addresses through /30; /31 includes both, /32 includes one.
Explicit hosts and range endpoints are retained, including .0 and .255.
Overlapping intervals are merged and unique addresses counted before bounded
expansion. Maximum 1024 unique addresses and 16384 selected TCP host-port
checks. All entries are validated before work begins; every unique address is
tested once through the same worker pool and combined progress counters.

POST /api/jobs permits multiline targets up to 16384 bytes only for discover
and ping/tcp with options.scope="subnet". Other tools retain the 2048-byte,
single-line target guard. NUL bytes are rejected. The diagnostic scope parser
also enforces the 16384-byte bound. Numeric TCP lists accept comma, semicolon
and ASCII whitespace separators and inclusive ranges such as 8000-8010.
Duplicate ports count once. Empty comma-separated port items remain invalid;
repeated whitespace and semicolon separators are ignored within each item.

One host worker pool serves ICMP, TCP, optional identification and hostname
lookup sequentially per host. ping/tcp concurrency 1..64 defaults to 32;
Discovery defaults to 16.
Each host is tested
directly, without requiring an earlier ICMP response. Ping sends exactly one
echo per address, ignoring single-target count/interval. Discovery sends one
echo and all selected TCP ports, with local context collected once. Discovery
permits 64 selected ports; TCP permits 1024, both subject to the total connection
limit. identify=true adds a bounded 2500ms UPnP attempt for Discovery/TCP. It
defaults to false for TCP and true for Discovery, and is ignored for Ping.
Discovery resolveHostnames defaults to true and adds one logical lookup per
address, with a 1500ms deadline, to requestedProbes/completedProbes. It shares
the same host concurrency limit. Ping/TCP subnet scope does not add reverse
lookups. A cached name is metadata and never response evidence.

NetworkToolkitSubnetPlanner is a pure embedded browser/CommonJS helper:
parseIPv4,formatIPv4,parsePrefix,calculate,classify,defaultParentPrefix,page.
Calculator input accepts IPv4, IPv4/CIDR, IPv4/dotted-mask or an address and
dotted mask separated by whitespace. Masks must be contiguous. Bare IPv4

selector. Prefix changes preserve the entered address as the anchor.
The shared diagnostic scan parser and scan limits are unchanged.

calculate returns numeric addresses plus formatted network, mask, wildcard,
upper/first/last addresses, counts and a note. /0 spans 4294967296 addresses
and represents the default route; its upper address is limited broadcast.
/31 uses two point-to-point endpoints and /32 one host route; their separate
broadcast/broadcastAddress fields are null. Counts are conventional arithmetic,
not evidence that addresses are assignable, available or reachable.
classify describes the entered address's leading bits independently of CIDR:
A/B/C have historical defaults /8,/16,/24; 0/8 and 127/8 retain Class A with
special-use notes. D is multicast and E reserved, with null default masks.

Possible networks starts collapsed and derives its base directly from the
entered address and selected mask/CIDR, independently of historical class.
The automatic base prefix is floor(selected prefix/8)*8. Fully masked octets
stay fixed; the partly masked octet enumerates aligned network boundaries.
For 192.168.19.1/21 this gives base 192.168.*.*, with 32 networks from
192.168.0.0/21 through 192.168.248.0/21. Exact /0,/8,/16,/24,/32 yield one
row at their respective base; /31 yields 128 point-to-point rows within /24.

at most 128. Historical class and its default mask are informational only.

it is no longer an end-user setting. This is separate from splitting the
selected subnet into smaller networks.
page({address,prefix,parentPrefix?,filter?,sort?,page?,pageSize?}) returns
classInfo,selected,parent,parentPrefix,basePattern,networkCount,total,page,pageSize,
pageCount,firstResult,lastResult,currentSubnetPage,filter,sort,rows.
networkCount is the full parent count; total is the filtered count. Counts
through 2^32 remain exact. Arithmetic interval intersection and page generation

An IP filter selects its containing child; a CIDR selects intersecting children.

row.index is the zero-based ascending parent index, ordinal is index+1, and

filtered out. Empty results have page=1,pageCount=0,firstResult=lastResult=0.

prefix, the full address for /32, or CIDR for an explicit non-octet prefix.

automatic list. Current subnet scrolls to and focuses its highlighted row,

CIDR; list copy and CSV use all current filtered, sorted rows. The
independent Split into smaller subnets remains capped at
256 children and retains its own CSV export. Neither calculator runs probes.

Standards: RFC 791 section 3.2; RFC 1112 section 4; RFC 4632 section 3.1;

LINKED WORKSPACE VIEWS (1.10.0)

POST /api/terminal-views/workspace {workspace} -> HTTP201 {view,viewState,url?}
  Moves zero to 64 retained home-owned sessions, including connecting,
  awaiting_input, closed and error states. Connected-only single-session
  detachment remains available through POST /api/terminal-views.
  One linked workspace at a time per owner. It counts toward the eight-view
  limit and keeps the original engine alive even when empty.
  workspace: {sessions:{ID:ScreenSnapshot},panes:[ID|""],active,paneFocus,
    maximized,display?}. Panes holds at most four distinct session IDs.
  ScreenSnapshot retains the single-session validation; combined data and
  emulator payload is limited to32MiB, request body40MiB. Display settings
  have a1MiB bound and use the nonsecret terminal settings allowlist.
  ViewInfo adds workspace:true and sessionIds:[]. Bootstrap supplies these
  fields. Current/snapshot responses use workspace and sessions[] with
  viewState, and checkpoint/reattach requests use {workspace} for groups.

A ready workspace capability can POST /api/terminals. Registration, owner
revision and workspace membership are committed under the same ownership
lock. Close/reattach cannot leave a delayed Connect request creating an
unowned transport. All new connections remain explicit; profiles do not
connect automatically. Credentials are submitted only in a Connect request
and are absent from transferred display settings/screens.

Group checkpoints must include every retained owned session, preserve each
screen's monotonic event cursor and retain the correct transport type. A
fresh child-created session keeps a replay cursor from before Connect so
closing before the first checkpoint can recover its available output.
Return and acceptance move ownership as a group while keeping the same
manager, sockets, pending prompts and session IDs. Home close preserves all
members, and an empty linked window can still create connections afterward.

All selected-session input/resize/respond/control/disconnect/delete requests
include X-Terminal-Revision. Missing defaults to0 for never-moved sessions.
Wrong view, stale revision or unready display returns409 before queue mutation.
A session with an active transfer/view cannot be removed by the home window.
Connect's final home-live check and registration share the same ownership lock;
a slow request cannot create a hidden session after home close.

Scoped single-session views can access only their own session/event data,
minimal status, transient display preferences and current-view routes.
They cannot create connections. Linked workspace views additionally create
and manage connections in that workspace and can enumerate serial ports.
Neither can enumerate other views' sessions, access global trust lists, run
diagnostics, change local configuration/storage, launch external apps or
shut down the owner. Their shutdown
route returns the view; global API Host/Origin/fetch-site guards still apply.

One feed serves every pane in a renderer. Pause/abort and drain write/resize
queues before capture/restore; stale fetch generations do not advance cursors.
Per-session sequence deduplication makes global replay rewind safe for other
panes. Restore runs against the pinned xterm6/serialize0.14 runtime and validates
before mutation. On failure input remains blocked and the saved checkpoint is
retained for retry. Do not acknowledge a failed display restore.

Native pulses every2s. Opening timeout45s, detached lease15s, requested return
fallback10s. Full app stop cancels the server base context, drains HTTP, forces
remaining connections closed, waits its handler barrier, closes transports and
waits child native windows before app-data maintenance.

Split preferences are {kind:single|columns|rows|three|grid,columnRatio,rowRatio}.
Ratios clamp0.2..0.8; no live session IDs/focus/screen are stored. Up to4 xterm
objects are visible and reparented across layouts. Fit timers are blocked during
handoff/restore; only the focused pane receives keyboard/toolbar actions.

TERMINAL WELCOME AND MOVE CONTROLS (1.10.4)

Empty panes and unused terminal tabs show the shared connection welcome with
explicit SSH, Telnet and Serial actions. The pane grid remains visible in an
all-empty split layout. Remote-owned, disconnected, failed and retained
session screens keep their status/transcript instead of receiving an empty
welcome. No connection starts without submitting its connection form.

Unused tab identities belong to a separate UI-only collection, limited to64.
They are absent from terminalSessions, API session IDs and stored preferences.
Workspace snapshots translate unused pane entries to empty strings and retain
the existing layout; only actual sessions are included in screen snapshots.
The saved workspace schema and terminal transport endpoints are unchanged.

A connection request captures its originating pane, draft and dialog identity.
Its completion must not close or clear a newer dialog, replace another pane's
session or use focus changed by a later workspace return. When its original
destination is unavailable, the new real session remains available in its tab.

One toolbar move/return control replaces the concurrent workspace/session
Detach buttons and repeated Reattach controls. It offers scope when meaningful,
keeps active-session eligibility checks and supports empty-workspace detach.
The independent terminal-window launch remains a separate operation.

COMPACT CONFIGURATION AND TERMINAL INTERACTION (1.15.0)

navigationCollapsed is a boolean desktop preference. The <=1100px drawer
uses independent transient state. configurationSections is a bounded map of
boolean tool.section entries; configurationNetworkTab is local,routed or
selected. Native details click changes persist synchronously before navigation
can remove the DOM node. The compact workspace switch uses the actual panel
width (<1120px), including changes caused by collapsing primary navigation.
Closed option groups retain their form elements and current-value summaries.

terminalInteraction is a bounded, nonsecret display preference:
  copyOnSelect:boolean (default true), copyOnClick:boolean (default true),
  rightClick:paste|menu (default paste), ctrlC:send|copy-selection (default send),
  menuItems:unique built-in IDs only.
Allowed menu IDs: copy,copy-line,copy-token,paste,select-all,search,clear,export,
zoom-in,zoom-out,reset-font,fit,maximize,control-c,reconnect,disconnect,move.
Unknown fields/IDs and malformed values are normalized before persistence or
window transfer. The independent workspace inherits preferences on first use;
linked session/workspace displays carry them under the existing ownership
protocol. No connection or network protocol changes are introduced.

Native ClipboardEvents, clipboard-read actions and xterm.paste all use the
same paste gate. Any CR/LF opens an editable, prefilled review. A trailing
newline also requires confirmation. Single-line input passes directly through
xterm's original paste implementation. Confirmation preserves bracketed paste.
The destination includes the entry, emulator, ownership revision and focus
epoch. Focus/page/ownership/connection changes invalidate in-flight reads and
reviews, including changes away and back to the same terminal. No confirmation
selects a different terminal or automatically connects. No empty paste input
fallback is used; native Ctrl+V remains usable without Clipboard API access.
The existing 1MiB queue limit includes bracketed-paste framing.

Selection auto-copy is limited to user gestures and serialized with explicit
clipboard writes. Explicit copy cancels pending automatic copy. Ctrl+C defaults
to the device even with a selection; optional selection-copy mode falls back to
Ctrl+C input when nothing is selected. Ctrl+Shift+C always copies. Ctrl+wheel
changes terminal font size, retaining the 10..24px bounds. Right-click supports
configurable paste/menu with Shift inversion; the keyboard menu is accessible.

terminal-copy reads public xterm buffer cells, assembles wrapped logical lines
and uses highlighter token spans. It never copies the original ANSI/OSC stream
or adds an Enter. A hover control copies a line; ordinary focus clicks do not.
Token clicks are drag-aware, preserve normal text selection, and yield to mouse
tracking. Snapshots reject changed output instead of copying another row.
Explicit copy gestures suppress generated mouse/focus input, including the
fallback clipboard transfer. Helpers and event subscriptions dispose with the
terminal. Success highlight decoration no longer adds a left border.

WINDOWS CLIPBOARD PERMISSION (1.15.0)

The PermissionRequested handler starts with DENY. The only exception is

PASSWORD MANAGER AND PASTE TRANSACTIONS (1.15.0)

1.15.0 OUTPUT BLOCK HANDOFF
Terminal screen snapshots accept optional outputBlocks with version 1, a
selected choice, bounded session overrides, and up to 50 command/paste block
records. Records contain normal-buffer row positions, command echo positions
and timestamps. Raw keyboard input and clipboard text are not transferred in

and deep-clones the metadata. This transient object is not application state.

1.16.0 VISIBLE SESSION COMMANDS AND INPUT EDITING
The active session commands are rendered in a visible console row. Display
preferences retain their own popup; they do not contain connection commands.
A disconnected console centers its reconnect and permitted new-connection
actions. Viewing output hides that card without replacing the session display.

POST /api/terminals/{id}/reconnect accepts an empty JSON object and the existing
ownership revision. It reuses the original private ConnectRequest, keeps the
session ID/window, clears queued old input and advances the ownership revision.
The request is retained only in terminal manager memory, never in application
settings, events, reports or view snapshots. Device authentication challenges
and host-key verification remain part of the normal protocol.

Accepted user input begins command tracking. Mouse/focus reports, terminal
replies, copy gestures and automatic pager responses are excluded. Output
actions refresh after terminal parsing as well as normal status refreshes.

An optional input:{line,offset} in version-1 outputBlocks records the visible
unsubmitted input anchor. Line is 0..10300 and offset is 0..8192. The live view
registry validates and deep-clones it. Raw keystrokes are not stored here.
Click-to-position and selected-input replacement operate only in the normal
buffer, current owned connected session and valid visible input range. Native
mouse-reporting/full-screen applications retain their input. Editing emits
cursor/backspace sequences without Enter and observes the existing input
queue and ownership guards. Replacement for a reviewed paste occurs only
after confirmation, with edit bytes included in the combined queue limit.

RECONNECT CURSOR CONTINUITY (1.17.1)

Reconnect output first cancels an incomplete sequence and saves the active
cursor (DECSC), then leaves the alternate screen (DECRST1049) and resets input
modes. Saving in the normal buffer replaces a stale cursor before1049 restores
it. Saving in the alternate buffer leaves the normal buffer's saved cursor
intact. The notice and replacement transport append on fresh lines after the
previous normal-buffer entry. No screen clear or terminal reset is performed.
After the reconnect API accepts the original session, the UI resumes Auto
scroll and scrolls that same terminal to the bottom. Session/tab/pane identity,
retained output, ownership revisions and queued-input safeguards remain intact.

PACKET DETAILS CONTINUITY (1.17.1)
