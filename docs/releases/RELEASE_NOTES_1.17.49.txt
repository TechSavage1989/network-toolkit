NETWORK TOOLKIT 1.17.49 PORTABLE
24 October 2026

SFTP SAVED SSH PROFILE - USE CONNECTION
- The SFTP Client's combined Connection source picker now activates a saved
  SSH terminal profile when Use connection is selected. It does not merely
  load its fields and require a second hidden action.
- Saved profiles containing a protected password or SSH private key authenticate
  using the shared Windows credential manager without persisting secrets in
  preferences, browser settings or documents.
- Profiles without linked credentials display an on-demand sign-in form
  supporting SSH password or private key (inline OpenSSH/PEM or key-file path),
  with optional key passphrase. Temporary credentials remain in application
  process memory for further browsing requests until the connection is changed.
- An unknown host key triggers an inspection and requires a separately verified
  SHA-256 fingerprint typed by the user. The connection remains blocked when
  the verified value does not match the inspected host key. Trusted hosts already
  recognized by Terminal continue without extra host-key prompts.
- A saved profile can be retried after an authentication/network interruption
  without losing transient sign-in details. Manual and active-session selections
  clear saved-profile identity and transient secrets, preventing mixed auth.
- Fixed the connection-source action staying disabled after successful SFTP
  connections; the button and status are synchronized for both active terminal
  and independent SFTP connections.
- On successful saved-profile connection, the SFTP connection settings panel
  collapses so more vertical space is available for the file browser.

COMPATIBILITY
- Preserves current shared SSH terminal SFTP sessions, FTP/FTPS profiles,
  terminal-side file browser, transfer functionality, local and remote text
  editor, theme options, icon choices, saved state and other 1.17.48 features.
- SSH servers must support the SFTP subsystem. Reusing the existing SSH
  terminal still needs no second authentication; saved profiles open an
  independent SFTP connection because the profile is not a live session.

VALIDATION
- JavaScript regression tests include four new saved-profile tests covering
  protected credentials, no-credential sign-in, unrecognized host keys,
  and preserving an in-memory password during a retry.
- Chromium UI tests cover eight saved-profile scenarios, including terminal
  connection switching, typed-password and private-key authentication,
  fingerprint mismatch handling, retry, and clearing temporary credentials.
- All baseline Go tests and JavaScript tests pass.
- The Windows x64 GUI executable builds from the full editable Go/HTML/JS
  sources. The archive is checked for integrity and includes checksums.

LIMITATIONS
- Native Windows GUI and physical SSH host authentication were not tested in
  this environment. Chromium tests use simulated local endpoints and are not
  proof of compatibility with all device SSH servers.
- Unrelated native Windows Explorer drag-out limitations and text editor format
  limits from 1.17.48 remain unchanged.
