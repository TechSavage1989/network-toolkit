NETWORK TOOLKIT 1.17.60
Visible update restart and versioned launchers

- GUI relaunch no longer uses the hidden helper's SW_HIDE launch settings.
- Update startup is acknowledged only after the native interface has finished
  loading and its main window is visible, not during the early status request.
- The native window explicitly recovers visibility when launched by an older
  updater with hidden startup flags. This applies on first upgrade to 1.17.60.
- Exact official versioned EXE names get a new current-version filename after
  healthy startup. Earlier filenames remain compatibility launchers so existing
  shortcuts still work. Custom executable names are left unchanged.
- Compatibility targets must be the exact official same-folder filename,
  validate as the expected product/version, and match a stored SHA-256 hash.
- Future updates allow 90 seconds for startup and retain progress logs,
  plus the previous EXE and rollback behavior. Settings are never migrated.
- Update settings show the current executable and versioned launcher paths;
  the reopened UI reports the running update version.

BOOTSTRAP NOTE
1.17.58/1.17.59 use their OLD helper when upgrading to 1.17.60. The visible
startup/readiness and naming changes run in the new app on that first upgrade.
New helper launch settings, longer timeout and extra logs apply to updates
started FROM 1.17.60. Existing helpers retain their 45-second timeout.

VALIDATION LIMIT
Automated Linux tests and Windows cross-compilation are not a live Windows
WebView2/update test. Native Windows behavior still needs real-device validation.
