NETWORK TOOLKIT 1.17.56
Released: October 24, 2026

STANDALONE SFTP CONNECTION REUSE
- Root cause: standalone browser operations used the one-shot diagnostic
  SFTP path. Every operation dialled SSH and authenticated again. Terminal
  browsing already reused its authenticated SSH client.
- New and saved SFTP client connections now keep an authenticated SSH
  transport open for their full session.
- Terminal and standalone SFTP use the same shared SSH connection code:
  authentication, algorithm policy, client identification and keepalive.
- File operations use the same SFTP channel runner as Terminal browsing.
- After connecting, browser requests use an opaque connection ID rather
  than resending connection credentials for each file action.
- Directory listings, previews, editor reads/saves, copy, upload, download
  and native drag operations all use that authenticated transport.
- Existing active Terminal connections continue using their live SSH client.
- Saved profile timeout and compatibility settings remain in effect.

ACTIVE SESSION TOOLS
- Added a toolbar outside the sidebar: Disconnect, Reconnect, Open terminal,
  Refresh files and Connection settings.
- Standalone Reconnect explicitly closes the old connection and creates a
  fresh authenticated connection using the current profile/settings.
- Open terminal adds an interactive shell to the existing SSH transport.
  It does not perform another SSH login. Terminal then owns the transport
  and the SFTP tool borrows that same Terminal connection.
- Servers that reject interactive shells remain usable in SFTP.
- When borrowing Terminal, Disconnect browser detaches file browsing and
  leaves Terminal connected. Refresh connection refreshes its SFTP channel.
- Reconnecting invalidates old editor connection bindings. Promotion over
  the same transport keeps existing editor bindings usable.
- Drag tickets are refreshed after promotion so old connection capabilities
  cannot remain cached under the new Terminal session.

SESSION LIFECYCLE
- Explicit disconnect and lost connections invalidate their connection IDs.
- Requests never silently reauthenticate a disconnected connection.
- Closing the main application window closes its standalone file connections,
  including when detached Terminal windows keep the engine running.
- A maximum of eight standalone SFTP transports may be active.
- Host-key verification remains required. Credentials stay in memory or in
  the existing protected credential vault, outside normal settings/history.
- Interactive authentication challenges can be completed in Terminal and
  that authenticated session selected for SFTP, as before.

PACKAGE
- Windows x64 executable with compile-time embedded icon/version resources.
- Complete editable Go/web source, vendored modules, build scripts and tests.
- See VALIDATION.txt for checks and platform limitations.
